## Testing

**Twenty seconds first.** The machine reaches its steady rate in seconds; if 20 s
does not answer the question, lengthen in 10 s steps. Long runs are for memory
slope, stall hunting and overnight stability — never for a yes/no check.

```bash
cd UI/Launcher
SOAK_NOCLEAN=1 SOAK_FREQ=10000 SOAK_TICK_S=10 node tools/soak.mjs 0.4
```

The CSV it writes is the instrument. Columns worth knowing:

| column | reads |
|---|---|
| `admit_s` / `sorted_s` / `na_s` | parts in, parts judged, parts unmatched. **`sorted_s ≈ admit_s` is a healthy machine.** |
| `tagSeen` | judge reports the probe actually examined. **Read this before any grading number.** |
| `tagApplied` / `tagDrift` / `gradeMismatch` | per-製程 limits reached the verdict / disagreed / core-vs-screen disagreement |
| `stall_max_ms` vs `task_max_ms` | both high = our JS; `task_max_ms ≈ 0` = the thread was not scheduled at all |
| `rep_bytes` / `rep_lean` / `cal_hits` | inspection record size, size after the archive strip, hits in it |
| `domNodes` vs `dom_nodes` | in-document (the signal) vs getDOMCounters (noise, see caveats) |

## Diagnosing "everything is NA"

This cost most of a night. The order that works, cheapest first:

1. **Is there an image?** `SOAK_FRAME_PNG=1`, look at `frame_live.png`. A black
   frame is not a software problem.
2. **Is the light on?** The backlight is a ~600 µs strobe fired by the stage
   task; the firmware refuses a manual hold outside IDLE. To see the scene:
   `SOAK_IDLE=1 SOAK_LIT_SNAP=1` holds `L1A` steady and fires one shutter. At
   the production 50 µs exposure a lit frame reads mean ≈ 91; ambient alone
   reads mean ≈ 0.05.
3. **Is it the 製程?** Run the same 20 s under another tag. A tag that produces
   `sorted 0.0/s` while another gives 19/s is a def problem, not an optics one.

**Do not** conclude from a bright 2448×2048 frame that the camera is working —
that is the recipe's reference image sitting in the canvas. The probe reports a
signature before and after the shutter; if it says `IDENTICAL … NO new frame`,
nothing was captured.

**The actual cause on 2026-08-24 was a physically displaced backlight.** Every
software hypothesis before that was wrong.

## Contracts you must not break

Both are written up in `REPORT_EXTRA_AND_VERDICT_2026-08-25.md`. In one line each:

- **`extra`** — optional debug payloads live under a report's `extra` object,
  selected by `ST { "DEBUG_EMIT": {…} }`, and the archive strips that one key.
  Put the next debug payload there; do not add a sibling field.
- **`quality_essential`** — the only thing that decides whether a measurement
  counts toward the part. `rank` is visibility, folded into that one field on
  mount via a `rankN` tag. Never let a viewing control reach a verdict.

Two more, learned the hard way:

- **A per-製程 override row is merged into the shape with a full spread.**
  Anything on that row lands on the shape and then in the wire def. Persist a
  **whitelist** of data keys — a display field on that row stopped the machine
  dead today.
- **A root-level ST setting must not travel inside `MachineSetting`.** That path
  runs `load_clean_regions()`, where an absent key means "no clean regions", so
  a one-key payload wipes the station's clean areas. Use `__SEND_ST_RAW__`.

## Caveats — numbers that lie

- **A grading counter of 0 means nothing until `tagSeen > 0`.** With the
  backlight out of position every part was NA, `trackingWindow` stayed empty,
  and `gradeMismatch` / `tagDrift` / `tagApplied` all read a confident 0 for
  hours. That is "nothing was compared".
- **`tagApplied` is not measurable on flipped parts** and is skipped for them
  (`tagWhy: flip=N`). Every part on this bench is currently flipped.
- **There is no untouched root at runtime** — entering inspection writes the
  overrides into `shapeList`, and `loadedDefFile` is regenerated from it. Asking
  "does this override differ from the recipe" always answers no.
- **`Memory.getDOMCounters` is not a health signal.** It swings three-fold while
  the document never moves; a MutationObserver records zero insertions and zero
  removals in steady state. Use `domNodes`.
- **The soak's `queryObjects` census starves the renderer for ~8 s**, every
  2.2 min, which the soak then records as a stall burst. Four hypotheses were
  chased against those bursts before the instrument was found to be the cause.
  It is opt-in behind `SOAK_LIVEDOM=1` — leave it off when hunting stalls.
- **A check that cannot fail is not a check.** Three separate probe defects this
  week (wrong state path, wrong field name, a counter behind a filter) each
  reported a confident zero. `tagSeen` and `tagWhy` exist so that a zero can be
  told apart from a blind spot. Add the equivalent to any new probe.
