## 1. Firmware — memory corruption

**F1 and F2 as originally written were wrong about where the defect was**, which
is exactly why they were marked "needs re-reading before fixing". `MachineConfig.cpp`
serializes into an Arduino `String` and checks `overflowed()`; there is no
fixed-buffer defect there. The re-read found the real ones somewhere far more
used.

| | Defect | Status |
|---|---|---|
| F1 | `dbg_printf` / `msg_printf` advanced the write pointer by **`vsnprintf`'s return value**, which is the length it WOULD have written. A line longer than the 500-byte `dbgBuff` moved `str` past the end; the closing `sprintf` then wrote there, and `send_json_string` was handed a length bigger than the buffer and read past it too. `dbg_printf` is the `__UPRT_I_` macro used throughout the file, so the corrupting input is "somebody logged a long line". `msg_printf` was worse — its head formatted a caller-supplied `type` with a bare `sprintf`. **Reproduced with a canary: reported length 321 for a 40-byte buffer, canary SMASHED.** | **FIXED** |
| F2 | Seven of eight `serializeJson(doc, buf, sizeof buf)` sites sent silently **truncated** JSON. Only `get_running_stat` checked. Half an object on the wire is worse than nothing: the host's parser rejects it and a reply correlated by id never matches, so the caller blocks until its timeout with nothing pointing back here — it reads as a dead link. The ArduinoJson **7** upgrade made this more likely: `StaticJsonDocument<N>` is now a deprecated alias whose `capacity()` merely returns N, so the document heap-allocates and grows while the output buffer stays fixed, and `overflowed()` reports only allocation failure. A guard written against v6 semantics quietly stopped meaning what its comment said. | **FIXED** |
| — | `intArrayContent_ToJson` took a `jbuffL` bound and never used it (unbounded `sprintf` in a loop) and underflowed `MessageL` to ~4 billion on an empty array. It had **no callers**. | **REMOVED** |
| — | `numberStr[200]` filled by bare `sprintf`. The widest branch comes to ~159 characters so it fits today, but only as a property of the current format string. | **FIXED** (snprintf) |
| F3 | The SEL air valve latches: once tripped it stays tripped until a power cycle, with no path back through the protocol. **Not yet re-verified**, and it may be a deliberate design decision rather than a defect. | **OPEN** |

**Flashed and verified on a bench board (COM3), 2026-08-26.**
`tools/frame_integrity.py --port COM3` provokes the reachable trigger --
`recv_ERROR` logs the offending bytes with `dbg_printf`, so 600 / 1500 / 2000
bytes of garbage on the line all go through the path that used to overflow:

```
PASS  get_running_stat actually replied (a silent board must not pass)  -- n=22
PASS  no reply was a fragment
PASS  largest reply is within the buffer  -- 2616 of 3584 bytes
PASS  2000 garbage bytes: the error path actually logged something -- dbg frames=4 of 5
PASS  2000 garbage bytes: no debug frame exceeds the debug buffer -- longest=54, buffer=500
PASS  the board still answers PING after all of that
```

The largest live reply is **2616 of 3584 bytes** — 73% of the cap, so this was
not a theoretical concern; a few more fields would have started truncating.

Two things the probe got wrong first, both worth knowing:

- **921600 is the UPLOAD speed.** The link is 230400. At the wrong baud the
  probe saw nothing and still reported PASS, because "no malformed frames" is
  trivially true when there are no frames. Every assertion now requires replies
  to have arrived.
- **The host's framing is `json + *CRC16 + newline`.** After a protocol error
  the layer enters RESYNC and discards up to the next NEWLINE, so a probe that
  omits it sees `CLEAR_ERROR_OK` and then silence forever. That looked exactly
  like a firmware bug — "clear_error reports success and the board stays
  wedged" — and was written up as one before being checked against
  `uinsp_test.py`. It is the probe failing to speak the protocol.

## 5. Re-enabling flipped-part measurement

`BACK_SIDE_LIMITS_ENABLED` in `UI/WebUI/src/UTIL/backSideLimits.js` is `false`,
and the `_b` keys are stripped from the generated wire def as well — disabling
in the UI alone would have left the core still judging flipped parts on `USL_b`,
which is the same class of divergence the flag exists to end. The def **files**
keep their values; nothing an operator configured was destroyed.

Re-enabling requires **M1 (done), M4 and X2 together** — not one of them:

- **M4** — per-製程 overrides carry no `_b` keys (the `PERSIST` whitelist) and
  the margin editor has no back columns, so an override that tightened `USL`
  left `USL_b` at the root value. The override was a no-op for exactly the
  parts this bench runs.
- **X2** — UI aux geometry omits the flip term the core applies
  (`shapeVectorParse` vs the core's `angle *= -1` when `flip_f < 0`), so on a
  mirrored part the drawn aux point is not where the measurement was taken.

Two more are **suspected and unconfirmed**, and need an actual mirrored-part
run: arc caliper box status colours may misalign (core index 0 = UI index
`count-1`), and the search_point scan side may reverse on the wrong branch.
Both are moot while this is disabled, but they are geometry rather than limits,
so they would still apply if a flipped part is inspected at all.

## 7. The update path — what is built, and what is left

Built and tested this session:

- install is crash-safe — a failed rename can no longer take the working
  version with it (measured on the old code: the version was deleted)
- a process that never spawned no longer reads as "running"
- three taps on the splash re-enter the launcher's settings, on a machine with
  no keyboard
- prune protects the last known good — earned by **running three hours**, not
  by starting — and whatever `current.json` displaced
- the shell reads the update folder directly, skipping `.!sync` partials and
  `.Conflict.` copies
- the inspection UI says a version is waiting and lets the operator pick the
  restart moment, and fails safe under four kinds of broken or absent host
