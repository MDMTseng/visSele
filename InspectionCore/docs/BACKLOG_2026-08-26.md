## 1. Firmware — memory corruption

**F1 and F2 as originally written were wrong about where the defect was**, which
is exactly why they were marked "needs re-reading before fixing". `MachineConfig.cpp`
serializes into an Arduino `String` and checks `overflowed()`; there is no
fixed-buffer defect there. The re-read found the real ones somewhere far more
used.

| | Defect | Status |
|---|---|---|
| F1 | `dbg_printf` / `msg_printf` advanced the write pointer by **`vsnprintf`'s return value**, which is the length it WOULD have written. A line longer than the 500-byte `dbgBuff` moved `str` past the end; the closing `sprintf` then wrote there, and `send_json_string` was handed a length bigger than the buffer and read past it too. `dbg_printf` is the `__UPRT_I_` macro used throughout the file, so the corrupting input is "somebody logged a long line". `msg_printf` was worse — its head formatted a caller-supplied `type` with a bare `sprintf`. **Reproduced with a canary: reported length 321 for a 40-byte buffer, canary SMASHED.** | **FIXED** |
| F2 | Seven of eight `serializeJson(doc, buf, sizeof buf)` sites sent silently **truncated** JSON. Only `get_running_stat` checked. Half an object on the wire is worse than nothing: the host's parser rejects it and a reply correlated by id never matches, so the caller blocks until its timeout with nothing pointing back here — it reads as a dead link. The ArduinoJson **7** upgrade made this more likely: `StaticJsonDocument<N>` is now a deprecated alias whose `capacity()` merely returns N, so the document heap-allocates and grows while the output buffer stays fixed, and `overflowed()` reports only allocation failure. A guard written against v6 semantics quietly stopped meaning what its comment said. | **FIXED** |
| — | `intArrayContent_ToJson` took a `jbuffL` bound and never used it (unbounded `sprintf` in a loop) and underflowed `MessageL` to ~4 billion on an empty array. It had **no callers**. | **REMOVED** |
| — | `numberStr[200]` filled by bare `sprintf`. The widest branch comes to ~159 characters so it fits today, but only as a property of the current format string. | **FIXED** (snprintf) |
| F4 | A frame with **no `type` field** called `enterProtocolError` and LATCHED the link. But the framing worked: the bytes arrived, the CRC matched, the JSON parsed. A missing field is a semantic error and was being punished as a protocol one — `{}` on its own was enough to make the machine deaf until a `clear_error`. Now answered with `err:"missing_type"`, link untouched. | **FIXED** |
| F5 | A latched link said nothing about being latched. The 1 Hz SYSTIME heartbeat kept running, so from the host the board looked alive — the symptom recorded in three documents here as 「從主機看它是活的」 — while the core pinged a deaf device forever. A `latched` frame now goes out once a second with `since_ms`, the recovery command, and **`discarded`**, the byte count that separates "went silent" from "throwing away everything you send". Nothing is emitted on a healthy board. | **FIXED** |
| F3 | "The SEL air valve latches until a power cycle, with no path back through the protocol." **Not supported by the code**, on the same pattern as F1/F2 being in the wrong place. Every SEL-blocking path has a route back: `selSafeService` *guarantees* release after one blow width (`SEL_SAFE_AT_MS`); the `SEL1_ACT_COUNTDOWN` quota raises `SEL_ACT_LIMIT_REACHES`, self-resets to `-1` so it cannot re-fire, and `set_sel1_cd` sets it; `FAULT_SEL_SUPPRESS_N` counts down; `PLATE_RUNNING`/`DRY_RUN`/`SYS_STEPPER_DISABLED` are conditions, not latches. Read-only check — **not reproduced on hardware**, which needs the plate and stepper, not just a board. | **NOT REPRODUCED** |

`AUDIT_BACKLOG_2026-08-18` lists `{"type":"ping","x":[]}`, `{"type":"ping","x":{}}`,
`{"type":"get_running_stat","x":[]}`, `{"type":"set_setup","plate":{}}` and `{}`
as latching payloads. **Measured on the board: the first four are already
fixed** — that entry is stale — and only the bare `{}` still latched, which is
F4 above.

**Flashed and verified on a bench board (COM3), 2026-08-26.**
`tools/frame_integrity.py --port COM3` provokes the reachable trigger --
`recv_ERROR` logs the offending bytes with `dbg_printf`, so 600 / 1500 / 2000
bytes of garbage on the line all go through the path that used to overflow:

```
PASS  get_running_stat actually replied (a silent board must not pass)  -- n=22
PASS  no reply was a fragment
PASS  largest reply is within the buffer  -- 2616 of 3584 bytes
PASS  2000 garbage bytes: the error path actually logged something -- dbg frames=4 of 5
PASS  2000 garbage bytes: no debug frame exceeds the debug buffer -- longest=54, buffer=500
PASS  the board still answers PING after all of that
```

The largest live reply is **2616 of 3584 bytes** — 73% of the cap, so this was
not a theoretical concern; a few more fields would have started truncating.

Two things the probe got wrong first, both worth knowing:

- **921600 is the UPLOAD speed.** The link is 230400. At the wrong baud the
  probe saw nothing and still reported PASS, because "no malformed frames" is
  trivially true when there are no frames. Every assertion now requires replies
  to have arrived.
- **The host's framing is `json + *CRC16 + newline`.** After a protocol error
  the layer enters RESYNC and discards up to the next NEWLINE, so a probe that
  omits it sees `CLEAR_ERROR_OK` and then silence forever. That looked exactly
  like a firmware bug — "clear_error reports success and the board stays
  wedged" — and was written up as one before being checked against
  `uinsp_test.py`. It is the probe failing to speak the protocol.

## 2b. The background mask has been off for three months

`FeatureManager_sig360_circle_line.cpp` passes an empty `labelImg` into
`search_point_cv`, so `useMask` is always false. It was turned off in `874b9b08`
(2026-05-29, a `wip(M2)` commit) with the comment *"temporarily DISABLED for
edge-finding debugging"* — **1024 commits ago** — and the member it read,
`m_labeledImg_cv`, has since been deleted, so the commented expression could not
compile even if someone uncommented it.

The mask's job is to stop the scan locking onto background specks. **For three
months every caliper search point has been free to pick a speck over the real
edge.** That is worth weighing against the NG rate.

It also makes `mask_dilate` inert — the knob is honoured all the way down and
then has nothing to act on.

**Do not restore the label-based mask.** It belongs to the labeling pipeline
that SBM replaces — and SBM produces no labels at all: `FeatureManager_group`
takes a raw-gray fast path that skips binarize/CCL/contour outright and leaves
`ldData` empty, so there would be nothing to restore it from.

**And do not reach for `localization_include` / `localization_exclude`.** They
look like the answer and they are not. Those polygons are the **feature
generation** mask — where line2Dup extracts features in order to *find* the
part. This is a **measurement** mask — where a caliper scan may pick up an edge
once the part *has been* found. Using the localization ROI to bound a
measurement would restrict where edges can be measured to wherever somebody
happened to draw the matching region.

*(An earlier version of this entry said the localization polygons were the
successor. They are not; that was a conflation of two different masks, and it
had been written into the code comment as well.)*

**There is no successor, and that is the decision — not a gap.**

A polygon "measurement fence" was specified, built end to end and rejected the
same day (2026-08-26). It worked: a def without one was bit-identical, a def
with one gated at the sample level, and a fenced-out point said so. It was
dropped anyway, because the argument against it is better than the feature:

- A caliper's own `margin`/`width` **already** define the band the scan walks. A
  fence is a second, coarser copy of the same constraint — and duplicated
  constraints are what the rest of this backlog is about.
- Against locking onto a *different object*, the primitive's own region does the
  same job. If the boundary is tight enough for a fence to matter, the region
  can be tightened instead.
- The search point follows the part through the morph (`cm.convert`); a polygon
  is **rigid**. On a deforming part the fence stops tracking while the primitive
  keeps up, so it turns into a new source of false NA rather than a guard.
- If closer following is what is wanted, the answer is morph on the primitive,
  not a static polygon around it.

The implementation is in a `git stash` ("measure fence polygon (abandoned: the
primitive region IS the mask)") rather than deleted, so a revisit recovers it
instead of rebuilding it.

**What that decision cleaned up**, same day:

- `search_point_cv` no longer takes a mask at all. `labelImg`, `objLabel`,
  `isObjectPx` and the never-called `labelAt` are gone, along with the ring
  build. The note at the top of `SearchPointCV.cpp` says why, so it is not
  reinvented.
- `edge.mask_dilate` is retired with them — it dilated that mask, so it had been
  honoured all the way down to nothing since 2026-05-29. A def that still
  carries the key is **warned about**, not silently obeyed, and
  `EDGE_SET_MASK_DILATE`'s bit is left as a hole rather than reused so old dumps
  keep meaning what they say.
- A search point that finds no edge now says `"no edge over min_strength in the
  search band"` instead of a blank NA — the band or the floor is where to look.

None of that changes a measurement: the fixture def is bit-identical before and
after.

**OPEN**, blocked on the SBM polygon work rather than on a decision here.

## 5. Re-enabling flipped-part measurement

`BACK_SIDE_LIMITS_ENABLED` in `UI/WebUI/src/UTIL/backSideLimits.js` is `false`,
and the `_b` keys are stripped from the generated wire def as well — disabling
in the UI alone would have left the core still judging flipped parts on `USL_b`,
which is the same class of divergence the flag exists to end. The def **files**
keep their values; nothing an operator configured was destroyed.

Re-enabling requires **M1 (done), M4 and X2 together** — not one of them:

- **M4** — per-製程 overrides carry no `_b` keys (the `PERSIST` whitelist) and
  the margin editor has no back columns, so an override that tightened `USL`
  left `USL_b` at the root value. The override was a no-op for exactly the
  parts this bench runs.
- **X2** — UI aux geometry omits the flip term the core applies
  (`shapeVectorParse` vs the core's `angle *= -1` when `flip_f < 0`), so on a
  mirrored part the drawn aux point is not where the measurement was taken.

Two more are **suspected and unconfirmed**, and need an actual mirrored-part
run: arc caliper box status colours may misalign (core index 0 = UI index
`count-1`), and the search_point scan side may reverse on the wrong branch.
Both are moot while this is disabled, but they are geometry rather than limits,
so they would still apply if a flipped part is inspected at all.

## 6. ~~Reported by agents, NOT verified~~ — THE LIST DOES NOT EXIST

**Closed 2026-08-27.** This entry said roughly 75 findings from six parallel
agents were "recorded but unverified". They were not recorded anywhere. Four
documents refer to their existence; none contains them, nothing in git history
ever did, and the agent output was in a session that is gone.

So this sat on the backlog for a day as a whole batch of work pointing at
nothing.

**What was actually learned, and it is the only part worth keeping:** of the
findings that WERE spot-checked, the hit rate was poor.

| checked | outcome |
|---|---|
| *"a NaN measurement is judged SUCCESS"* | false — the guard is at `FeatureManager_sig360_circle_line.cpp:926` |
| *"20 crash dumps caused by divide-by-zero"* | false — 9 PRODUCER_DIED, 1 SIGSEGV, **0 SIGFPE** |
| F1 / F2 | real bugs, **wrong file** — they were in `dbg_printf`/`msg_printf` |
| F3 (SEL valve latches) | not supported by the code; every SEL-blocking path has a route back |
| X8 threshold | off by 10x on its own number — 100000, not 10000 |

Eight checked across two sessions, and **not one was correct as written** —
several pointed at something real while naming the wrong file, the wrong
threshold or the wrong mechanism.

**The lesson is about the method, not the list.** An unverified finding is not
a lead with a small error bar; it is a sentence that has to be re-derived from
scratch, at which point the finding contributed a search term and nothing more.
If this is done again, verification belongs INSIDE the loop that produces the
findings — an agent that must show the failing input and the line it fails on
produces fewer claims and all of them checkable.
