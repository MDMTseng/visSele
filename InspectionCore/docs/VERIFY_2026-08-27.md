# Verifying the 2026-08-27 audit fixes

Eight code changes from the agent-audit triage. What each one can and cannot
be shown to do, stated separately, because most of them are changes to paths
that only run when something is already going wrong.


That last row is the one worth having. **Every drop counter in this file used

see, the queue DEPTH, reads normal during exactly the load that is discarding
parts: the queue stays shallow *because* frames are being thrown away.

## Needs the machine — and why

| | what to do | what it proves |
|---|---|---|
| **C1** | `ST {"DoImageTransfer": false}` with a camera running | images STOP. Here `sCameraListCount:0`, so no frames flow and only "it did not crash" could be shown |
| **C2** | run CI with inspection behind (slow def, or `INSP_LATENCY_PAD`) | `acq_refused` climbs instead of staying 0 while parts go unjudged |
| **C3** | a long soak | the pool does not shrink. This is the one whose failure mode is CUMULATIVE — a slot per occurrence until acquisition dies with the camera still healthy |
| **C4** | a soak with the peripheral connected | `queue_dropped` stops moving when nothing was dropped |
| **C5** | a soak | the three threads survive whatever real frames throw at them |
| **C11** | force two NG snapshots in the same millisecond | two files, not one. Also just: look at a snapshot folder and check names now end `_<n>` |

**The single most valuable check is a soak**, because C3, C4 and C5 are all
changes to what happens when the pipeline is under pressure, and none of them
can be provoked from a shell without a camera.

## Cannot be verified by running, and should not be claimed

- **C8** — the deleted file was in no build target; the build proves it was
  dead, nothing proves it was harmless to delete beyond that. It is in git.
- **C7, C9, C10** — CONFIRMED and deliberately not patched. Nothing to verify.

## What a green soak would NOT prove

C3 and C4 are error paths. A soak where nothing goes wrong exercises neither,
and will pass whether or not the fix is correct. The honest reading of a clean
soak is **"no regression"**, not "the fix works".

To exercise them on purpose you would have to make the queues overflow —
slow the inspection down until `inspQueue` fills, and watch `dropped` and
`acq_refused` move while the pool size stays put.
