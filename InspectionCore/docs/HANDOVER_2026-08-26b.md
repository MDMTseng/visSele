## The one idea worth carrying forward

**A shared implementation makes drift reviewable. Only a shared expectation
makes it fail.**

That is not a slogan; it is what the day measured. Every serious defect found
was duplication, and in the worst case the *correct* version was already sitting
in the same file as the wrong ones:

| what | copies | outcome |
|---|---|---|
| arc span | **three**, one correct, one file | caliper width **11.00×** too wide |
| stale-hit fingerprint | **two**, two files | 6 of 6 def edits went undetected |
| caliper resolution | **four**, two files | 15 of 24 inputs disagreed with the core |
| "an empty statistic" | **two** | created that same morning, by me |

So the order for any future work of this kind is **contract first, restructure
second**. Restructuring after a contract is a mechanical move with a check
behind it. Restructuring before one is the process that produced that table.

Both contracts were **verified to fail** by reintroducing real bugs — a harness
that cannot fail is not a harness:

```
B3 (pt2-blind arcSweep)     4 of 37 fail, worst anchor 2.000e+1 (a full diameter)
B2 (no execute-stage floor) 7 of 37 fail, e.g. arc count 2 -> core 3, webui 2
S1 (stats ignore the 製程)   3 of 16 fail, incl. the histogram range staying stale
```

## Where geometry comes from, by situation

Only the first row needs a second implementation. This was not obvious and is
worth not re-deriving:

| when | source | state |
|---|---|---|
| **dragging a point** | the UI predicts — the core has not run | unavoidable; this is what `geom_contract` bounds |
| **on CHECK** | the core, over `II` + `definfo` + `imgsrc:"__CACHE_IMG__"` | exists in `DefConfUI.js`; the reply is never compared with what the UI drew |
| **during inspection** | the core's report | now actually used — X1/X7 fixed |

**CHECK stays manually triggered.** Firing that round trip on mouse-up is the
obvious-looking improvement and it is wrong: operators deliberately park shapes
in imperfect states, and an auto-refit would undo what somebody meant. What can
hang off it for free is comparing the core's reply against what the UI drew, at
the moment the operator already pressed the button.

WASM for the shared geometry was considered and rejected as overkill here: the
divergences were duplicate copies and a misread two-stage rule, not porting
errors, and `resolveCaliper` is parser policy rather than geometry so WASM could
not have covered it anyway.

## Contracts added

To the ones in the previous handover:

- **Requiredness must be scoped to an opt-in container.** A new *scalar* field
  can never be required — every def written before it existed lacks it, and
  those only accumulate. A feature introduced as an *object* can be: the
  container's presence is the opt-in. `edge` is the working example, and it is
  why the `min_strength` rule is safe rather than a fleet-wide outage. Prefer an
  object over loose scalars **precisely so that requiredness stays possible**.
- **Ask "has the def changed" with a blacklist of results, not a whitelist of
  fields.** A whitelist is silently wrong until somebody notices.
- **`SHAPE_RESULT_KEYS` answers two questions that must never differ**: what is
  stripped before the def is hashed, and what is ignored when deciding whether
  the def was edited. Add a new per-frame field to it or the def bloats *and*
  every shape reads as edited the moment it is inspected.

## Firmware

Flashed and verified on a **bench board (COM3)**, not the machine.

`dbg_printf`/`msg_printf` advanced their write pointer by `vsnprintf`'s return
value — the length it *would* have written. A log line longer than the 500-byte
`dbgBuff` walked past the end, the closing `sprintf` wrote there, and
`send_json_string` was handed a length bigger than the buffer. Reproduced
against a canary: **reported length 321 for a 40-byte buffer, canary SMASHED**.
The trigger is reachable from the wire — `recv_ERROR` logs the offending bytes,
so any garbage on the line longer than the debug buffer went through it.

Seven of eight `serializeJson`-into-a-buffer sites shipped silently truncated
JSON. Half an object reads as a dead link: the host's parser rejects it and a
reply correlated by id never matches. The ArduinoJson **7** upgrade made this
more likely, not less — `StaticJsonDocument<N>` is now a deprecated alias whose
`capacity()` merely returns N, so the document grows while the buffer does not,
and `overflowed()` reports only allocation failure. **The live
`get_running_stat` reply is 2616 of 3584 bytes — 73% of the cap.**

A latched link now says so once a second, carrying `since_ms`, the recovery
command, and **`discarded`** — the byte count that separates "the board went
silent" from "the board is throwing away everything you send". Those look
identical from the host and are different problems. Nothing is emitted on a
healthy board, and it is a separate frame from `SYSTIME` because three
diagnostic tools parse that line's exact text.

**Still to do: flash a production machine.** Only the bench board has it.

## Caveats added

- **The background mask has been off since 2026-05-29** — `874b9b08`, a `wip`
  commit, "temporarily DISABLED for edge-finding debugging", three months and
  more than a thousand commits ago (the exact count only grows, so trust the
  date).
  `m_labeledImg_cv` has since been deleted, so the commented line could not even
  compile. Its job is to stop the scan locking onto background specks, so for
  three months every caliper search point has been free to pick one. **Do not
  restore it** — SBM produces no labels at all (`FeatureManager_group` takes a
  raw-gray fast path that skips binarize/CCL/contour and leaves `ldData` empty),
  so there is nothing to restore it from. **There is no successor**: a polygon
  fence was built and rejected on 2026-08-26 (the caliper's own margin/width
  already bound the scan, and unlike a rigid polygon a search point follows the
  morph). `search_point_cv` no longer takes a mask, and `mask_dilate` was
  retired with it. See BACKLOG_2026-08-26.
- **`localization_include`/`localization_exclude` are NOT that successor**, and
  this document said they were until it was corrected. They are the **feature
  generation** mask — where line2Dup extracts features in order to *find* the
  part, authored in `SBMStudio`. The dead mask is a **measurement** mask — where
  a caliper scan may pick up an edge once the part *has been* found. Wiring the
  first into the second would bound measurement by wherever somebody drew the
  matching region. The real successor is a separate object polygon mask, planned
  and not yet specified.
- **`blur` was a knob that did not exist.** `search_point_cv` took a `blurSize`
  and never read it. Deleted rather than surfaced in the UI: a control that does
  nothing is the defect class this audit exists to remove.
- **The agent findings keep being wrong about specifics.** Four checked, four
  wrong: F1/F2 named the wrong file, F3 is not supported by the code at all, X8
  was off by 10× on its own threshold. The underlying concerns were often real —
  the *details* were not. Verify each before acting; do not transcribe.

## If the reducer gets restructured

`UICtrlReducer.js` is 1257 lines and **one case is 674 of them**. It is worth
splitting, but the shape matters: **one module owning the sequence**, not ten
small files. The case should still read top to bottom as "what happens to a
report", each step named rather than inlined. If the order of operations stops
fitting on a screen, the extraction went the wrong way — scattering logic is how
you come to miss a piece when integrating, which is exactly the table at the top
of this file.

`pipeline_contract.mjs` exists so that move can be checked rather than trusted.
