## 1. State: what is now true that wasn't

**Core — the measuring instrument no longer lies (Tier 1, all closed).**
value_A==value_B can't NaN a part into PASS; a caliper band off-frame measures
instead of inventing (the old behaviour was rms 1.99mm presented as a
measurement); degenerate fits can't return the def's nominal as "measured";
malformed calib files are refused instead of green-ACKed; refused camera
setters land in `camera_info.setup_failed` (which immediately caught the fake
camera silently ignoring blacklevel/gamma); `station.skip_inspection` /
`ignore_calib` are on every frame.

**Core — a dead sorter link is visible (was: UI green, nothing sorting).**
`perif_pairing.link` carries tx_fail / tx_fail_consec / dropped_no_channel /
suspect; a suspect link declines CONNECT reuse and reopens; Windows
`WriteFile`'s discarded BOOL (deployed platform!) is checked. One reading
rule: **any of these counters moving while parts run = the machine is not
sorting.** The WebUI now draws them (PerifStatus).

**Core — writes are durable.** SV (how the WebUI saves defs and
machine_setting.json) goes through tmp+fsync+rename; a full disk keeps the old
file. The snapshot-dir fallback no longer `exit(-100)`s the whole core.

**Core — WS layer.** Image stream defaults to JPEG 85 (was raw RGBA,
19.7MB/frame, 187x). One stalled browser wedges everyone for ≤ ~5s
(SO_SNDTIMEO + shutdown-on-failure) instead of forever; the sorter itself was
proven to keep running through a wedge.

**WebUI — peripheral layer is a module (`src/perif/`).** Perif_API_Base + 4
device classes out of script.jsx (-1100 lines), link state OUT of Redux
(module store + `usePerifLink`/`usePerifConn`; a 3s PING notifies that
device's subscribers, not every mapStateToProps in the app). Reconnect has
backoff; SUSPECT exists and is drawn. The ConnInfo reducer's perif cases are
gone.

**WebUI — the editor def is safe from inspection mode.** Tag-limit overrides
restore on exit (by value per overridden id — the first, identity-gated
version silently never ran; the E2E's console trace caught it). The station
panel read-merge-writes only its two keys into machine_setting.json, so two
browsers can't silently revert each other. The margin editor works on a clone
(the dirty check no longer says "no changes" while grading reads edits).

**The "1006 disconnect" is solved and was never the network.** queryCam saw
the idle fake camera (`cam_status != 0`), declared REMOTE_SYSTEM_NOT_READY,
and ALLOW_SOFT_CAM=false blocked reconnection → a ~5s SPLASH↔MAIN loop
forever. Dev builds now allow the soft cam; production unchanged. If SPLASH
cycling returns: check `cam_status` first (caminfo.mjs), not the network.

**Test infrastructure that didn't exist:** the `--insp` full-precision
leaf-diff gate (bit-identical golden after every measurement change, run ~12
times these two days), ~10 live webctl probes, and the WebUI flow suite at
9/9 including **inspCycle** — the operator's main road (recipe → real menu
entry → tag limits applied → exit → restored), with every choreography trap
it took to build written into its comments.

## 2. What will mislead you

- **The 10221 golden reads `machine_setting.json`'s `inspection_region`** and
  silently drops every label (0 objects, no error) if a uInsp station region
  is left over. Bitten twice. Remove/restore around the run.
- **inspection stream perf on this bench:** renderer CPU is ~24% streaming.
  The frozen-view **idle floor turned out to be one CSS animation, not polls**
  (see TODO 1, resolved) — the JS layer at idle is genuinely quiet: 0 rAF,
  0 draws, 0 DOM mutations, ~2 timer fires/s. The canvas double-draw is fixed
  (draw_INSP 10.3 → 5.1/s = one per frame) but that bought correctness, not
  CPU.
- The FI play button inspects the **recipe selected at MAIN**, not whatever an
  editor session holds. LD result acts are dropped outside the editor.
- Synthetic DOM events no-op on per-shape PropertySheets and antd controls —
  drive the UI only with webctld's real Playwright endpoints.

## 3. TODO, ranked

1. ~~**WebUI idle-floor investigation**~~ **RESOLVED 08-16.** The suspects
   (queryCam poll, SLID poll, rAF) were all innocent — instrumentation showed
   0 rAF / 0 draws / 0 mutations at idle. The floor was
   `DISCONNECT_Blink_ANIMATION`: a `background-color` CSS animation runs on
   the main thread and forces style+paint every vsync, so one
   disconnected-device button cost ~3.6 CPU points forever (5.2% → 1.6%
   paused; `step-end` timing does NOT help — Chromium ticks main-thread
   animations per frame regardless). Fix: blink via `opacity` (composited)
   over a static background — measured 5.2% → ~2.2% with the blink still
   running. Moral for future UI work: **never animate paint properties on
   long-lived status indicators; animate opacity/transform only.**
2. ~~**Camera state: poll → push**~~ **DONE 08-16 (doorbell form).** Core's
   `CamStateWatchThread` samples camera health at 1s under
   `camera_lifetime_lock` and, on CHANGE, pushes a tiny SS/GS/SS doorbell
   batch (pgID 0xCA11 — never CI_pgID, that would corrupt an in-flight
   inspection batch) to stream subscribers; the WebUI re-runs its normal
   camera_info query on receipt (all policy stays in Cam_Stat_Query) and the
   steady-state poll dropped 2s → 6s. Verified: watcher logs the boot
   NAK→ACK transition; client re-queries ~0.7s after a doorbell. Two facts
   discovered on the way: (a) a successful `camera_ez_reconnect` is
   ATOMIC under the lock — no observable transition, correctly nothing
   pushed; (b) `cam_status` really means "device answering", NOT
   "acquiring" (Aravis probes a register, BMP carousel is always ACK), so
   the old "SPLASH over an idle camera" framing was wrong — the idle half
   was entirely the ALLOW_SOFT_CAM policy loop, already fixed. Note the
   re-test trap: BMP_carousel constructs happily on a MISSING folder (0
   files) — you cannot fake a dead camera by hiding the folder.
3. ~~**Core WS layer locks (backlog 2.1 / 2.6)**~~ **DONE 08-16.** The map
   that made it tractable: senders were ALREADY serialized among themselves
   by BPG's `linkLayerLock` (the whole `fromUpperLayer`, image callback
   included, runs under it) — the unprotected parties were the main WS
   thread's own sends (PONG, handshake) and teardown. Fix: per-conn
   `sendMutex` funneling every send; `doClosing` = shutdown-now +
   deferred close/RESET via try_lock (the select loop never blocks behind a
   5s send; the fd cannot be recycled while a sender is inside send(),
   because close() itself is what recycles it); pool `find()` locked
   against `push_back` realloc; CLOSING handler holds `subscribersLock`
   across peers/default_peer/conn_peer (2.6). Verified with
   `webctl/churn.mjs` — 90 subscribed clients hard-destroyed mid-stream +
   one 5s-stalled client: stream wedges ≤5s (the known 2.8 bound,
   unchanged) then recovers, core alive. Win-cross NOT compile-checked
   (vcpkg configure fails on TIFF/OpenMP on this bench — pre-existing
   toolchain state, fix that before the next Windows deploy).
4. ~~**loadedDefFile resurrection**~~ **DONE 08-17.** triggerSave now
   guards overwrites of the def THIS session loaded: LD {filename} (pure
   read, FL reply) re-reads the on-disk file, compares its featureSet_sha1
   to the load-time hash, and a mismatch surfaces a Modal ("仍要覆蓋" /
   cancel) instead of silently resurrecting the session's stale copy of
   every field it never edited. Scope deliberately narrow: only when the
   target path IS the loaded def (a different existing file is the file
   picker's own confirm); legacy defs without a sha1 keep the old
   behaviour. Normal-path regression: flows 9/9. The dialog branch itself
   is logic-reviewed but not UI-automated (driving the file picker isn't
   built yet — in REGRESSION_TESTS gaps).
5. **Perif phase D** — **half done 08-16**: `perif_pairing.link` is now
   push-on-change (perif-state doorbell, pgID 0xCA12, same watcher as the
   camera one; counters in the change-key make it fire ≤1/s during an
   active fault — the exact window the old 10s poll was blind in), and the
   WebUI's health poll dropped to a 30s safety net with a single-flight
   guard (the pokeNow-fork lesson applied from birth). Verified on REAL

6. **BACPAC/MachineContext refactor** — **P0 done 08-17** (`309a762b`): the

## 4. The 08-16 review sweep (8 agents, both sprints) — what it changed

Two 4-agent review waves (concurrency, protocol, UI-semantics, test-coverage
on the day's diff; numerics, systems, WebUI-state, WS-interplay on the whole
7cad540e..ad9240ed sprint). Everything confirmed-real was fixed the same day:

- **`websock_data.type` was uninitialized** in the link layer's fromUpperLayer
  — stack garbage equal to CLOSING would have run doClosing() on a sender
  thread inside its own subscribersLock (self-deadlock) and broken the
  deferred-close design's main-thread-only invariant. One-line init.
- **`pokeNow` forked poll chains** when a doorbell landed while a query was
  in flight (two agents found it independently). inFlight + pokePending
  coalescing; verified live — doorbell storm now collapses into one 6s chain.
- **`usePerifConn` minted a fresh object every render** → MAINUI's readiness
  effect self-looped at commit speed for the whole duration of "camera
  reconnecting" on a uInsp machine. Memoized on the store snapshot.
- **WriteBytesToFileAtomic was not power-loss-durable on Windows** (the
  deployed platform): fsync was POSIX-only. `_commit` added.
- **lens_calibrate green-ACKed a diverged fit** the load-side guard would
  then refuse — reload-through-the-guard is now the produce-side validation.
- Also: doorbell batch is now atomic over the subscriber set
  (pushBatchToSubscribers); snapshot-dir fallback wrote to a mangled sibling
  dir (missing SEP); deliberate perif teardown no longer cries "verdicts NOT
  reaching the machine"; safeSend retries EINTR; station-save refuses instead
  of falling back to the cache (the fallback resurrected other browsers'
  deletions); the 10s perif poll no longer flips a locally-held SUSPECT green.

**Known and deliberately deferred** (analysis written, fix not rushed):

- `doClosing`'s synchronous CLOSING callback can still block the select loop
  ≤5s behind `subscribersLock` while a stuck subscriber's send times out —
  same bound as the known 2.8 wedge; the naive fix (snapshot subscribers,
  send outside the lock) re-opens a wrong-stream-injection window on slot
  reuse. Proper fix is generation-stamped peers; do it with the 2.8
  lock-structure rework. This ordering is also why churn.mjs never observes
  the `deferred close` branch: it is a safety net, not a working path.
- **win-cross builds again (08-16)**: the TIFF/OpenMP configure failure was
  stale-cache state (a clean reconfigure passes); the real breaks were
  `latency_stages` (openpty, POSIX-only — now gated `if(NOT WIN32)`) and
  the perif dev console (`sendmsg`/`netinet` — now stubbed on `_WIN32`; it
  exists for the Mac bench's exclusive serial port and has no Windows use).
  `./build.sh -p win-cross -c Release` → visSele.exe green, carrying the
  whole sprint (WS locks, _commit durability, doorbell).
- **`abs`→`fabsf` in ContourGrid's curvature filter: MEASURED, the Windows
  deploy WILL shift real measurements.** A/B run 08-16 on the Mac by
  replicating the old MinGW `int abs` truncation at the two filter sites
  (`--insp` full-precision leaf diff, station regions cleared):
  10321 = bit-identical; **10155 (the factory def): line fit loses ~19
  points (548→529) and judge #11 moves 1.9460 → 1.9922 mm (+46 µm)**;
  4444: 27 leaf diffs. The new behaviour is the correct one (the filter
  actually enforces lineCurvatureMax; the old Windows filter was
  near-inert), but limits tuned against old-Windows binaries were tuned
  against the inert filter — **near-limit parts can flip PASS/FAIL after
  deploy. Plan a revalidation of affected defs' limits at the next factory
  deploy; do not ship it silently.**
- wlsLine's `a+c < 1e-9` degenerate guard catches exact coincidence only; a
  def line with ~1e-3 px endpoint spacing still fits noise with ok=true.
  Needs a scale-aware threshold — golden-gated change, do deliberately.
- TCP half-open can briefly clear perif suspect (one successful send into a
  dead socket's kernel buffer); self-heals in 1-2 verdicts.

## 4b. Test infrastructure added 08-16/17

The suite grew from "does it run" toward "does it still measure/answer/route
the same, and does it survive abuse." New harnesses (all in
`UI/WebUI/tools/webctl/`, indexed in REGRESSION_TESTS.md):

- **`bpg_sweep.mjs`** — all 16 handled TLs × {valid, malformed, framing abuse},
  liveness after each. ~15%→~90% BPG shape coverage; found the PD crash (6.1).
- **`churn.mjs`** — WS teardown under fire (90 clients destroyed mid-stream +
  a FIN'd stalled client; fd-reuse clean-first-bytes probe; freeze-gap ≤6s).
- **`doorbell.mjs`** — camera + perif state doorbells end-to-end, with a
  steady-state suppression phase and REAL PD transitions.
- **`cycle.mjs`** — N-lap operator round-trip (editor + EX inst-check → recipe
  with alternating NG-range tags → inspection → restore + hash-stability). 15/15.

Full-stack still-missing (designs captured, see TODO 9): value-level board
verdict reconciliation, all-primitives measurement matrix, editor object-knob
tour. The `--insp` leaf-diff remains THE measurement gate; the QA suite
(`test_suite/qa/`, ~582 cases) already sweeps degenerate inputs but mostly
asserts no-crash, not verdict — the measurement matrix would upgrade that.
