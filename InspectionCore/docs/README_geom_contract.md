# The pipeline contract

`UI/WebUI/tools/pipeline_contract.mjs` asserts what happens to an inspection
report, end to end: the 製程 override reaching both the verdict and the
statistics, the bucket restarting rather than mixing limit sets, a def edit
invalidating caliper hits while an inspection result does not, the verdict
roll-up keeping an NG, and back-side limits staying disabled.

```bash
cd UI/WebUI && node tools/pipeline_contract.mjs
```

It bundles the real modules with esbuild using vite's own aliases, so it runs
the shipped code rather than a transcription — the same reason the geometry
vectors are generated by calling the core's function instead of copying it.

## Why it exists before any restructuring

The inspection path is a single **674-line switch case** in `UICtrlReducer.js`,
half that file. Everything fixed there on 2026-08-26 — S1, S2, B4 — had to be
found by reading it line by line, because a switch case cannot be called with an
input and checked.

The obvious next move is to pull that computation into named functions. **The
objection to that is real**, and the same day supplied the evidence: the worst
bugs found were duplication, not size.

| what | copies |
|---|---|
| arc span | **three**, one correct, all in one file |
| stale-hit fingerprint | **two**, in two files — changing one alone would have hidden every hit |
| caliper resolution | **four**, across two files |
| "an empty statistic" | **two**, the second created that same morning |

Extraction does not prevent any of that. Nothing stops a second copy appearing
in another file, and splitting logic across files is exactly how you come to
miss one when integrating.

What prevents it is a test that asserts the **answer**, wherever the code lives.

So the order is: **contract first, restructure second.** Restructuring after
this is a mechanical move with a check behind it. Restructuring before it is the
process that produced the four rows above.

## If restructuring happens

The shape to aim for is **one module that owns the sequence**, not ten small
files. The case should still read top to bottom as "what happens to a report",
with each step named instead of inlined. If, after extracting, the order of
operations is no longer visible in one screen, the extraction went the wrong
way — that is the cost this document's objection is about, and it is a real one.
