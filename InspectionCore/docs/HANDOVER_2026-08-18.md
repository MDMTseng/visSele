# Handover — 2026-08-17/18

Branch `ct/win-bench-bringup`, pushed through `0b3d5dbd`. Continues
[HANDOVER_2026-08-16.md](HANDOVER_2026-08-16.md).

The arc: bring the whole system up on a **Windows bench with a HikRobot
camera** for the first time. Everything else on this branch is what that
exposed. `master` is developed on macOS with Aravis, and the divergence was not
where anyone expected — not in the algorithms, but in a config sentinel, a
build-only code path, and a test suite that had never once run off that Mac.

Read this for the map. The reasoning is in the commit messages, the traps are
in [CORE0_1_CAVEATS.md](CORE0_1_CAVEATS.md), the open bugs are in
[AUDIT_BACKLOG_2026-08-18.md](AUDIT_BACKLOG_2026-08-18.md), and how to run any
of it is [REGRESSION_TESTS.md](REGRESSION_TESTS.md).

## 1. State: what is now true that wasn't

**The machine sorts.** `cat_ok`/`cat_ng` are declared in `machine_setting.json`
(`cat_ng: 1` → SEL1, `cat_ok: 3` → SEL3). Before that every part reported NA
and recirculated. The core now **refuses** a wiring with `cat_ng >= cat_ok`,
because the firmware breaks a duplicated verdict by keeping the numerically
smaller cat and calls that worst-wins — which is only worst-wins in that
order. Inverted, a duplicate promotes an NG to OK and the counter recording it
is still named `REP_REPEAT_WORSE_N`.

**The camera runs at 161 fps, not 8.** `default_camera_setting.json` says
`framerate: -1`, and `CameraLayer_Aravis` reads that as "disable the cap" while
`CameraLayer_HikRobot_Camera` only disabled it above 1000 — so `-1` *enabled*
the limiter and then failed to write, leaving whatever the camera had stored.
That was 8 fps against a plate announcing 18.8 objects/s. The camera dropped
more than half the triggers, the frames that arrived carried timestamps ~18 ms
from their object (`NOMATCH nd=18564`), and the run stopped with
`INSP_RESULT_MATCHES_NO_OBJECT` inside twenty parts. One config value, two
drivers, opposite meanings, and no test could have caught it because no test
touched a CameraLayer at all.

**`machine_id` is derived from the chip.** It used to be a settable string, so
it travelled inside any config export — and the everyday use of an export is
bringing a new machine up from a known-good one. Now `uI-<eFuseMAC>`, refused
by `set_setup`. Chosen over random-into-NVS for the case that happens: erasing
NVS to reset a machine. A random id comes back different and orphans every
record already filed.

**Whole-config export / import exists.** The firmware declares 30 settable
keys; the hand-built cards reached eight. The setup modal can now export the
lot as JSON and import it back, re-reading and diffing afterwards — `set_setup`
answers `ack:true` whatever it understood, so an import that only writes is an
import that cannot fail visibly.

**The regression suite runs on Windows.** It never had. Three unrelated
blockers, all fixed: `core.autocrlf` with no `.gitattributes` made every
byte-compared baseline fail with character-identical diffs; webctld's
Playwright profile lives inside vite's watch root and Windows' exclusive file
lock killed the dev server with `EBUSY`; and the harness dependencies had
simply never been installed. `flows.mjs verify` is 9/9.

**There is a suite that needs no hardware.** `suite_nohw.mjs` — 14 probes,
**11 pass / 2 skip / 1 fail** with nothing attached (2026-08-19). The one fail
is `qa/run.mjs` itself, carrying the four classified failures in `qa/SUMMARY.md`;
`flows.mjs verify` is 9/9 in 145 s and `cycle.mjs` passes. The qa layer joined
this suite on 2026-08-19, once it stopped being 21 SKIPs and 954 s of retries. The core falls back to
`BMP_carousel` and the WS still opens, which makes the protocol sweep, the WS
lifecycle probes and the whole UI flow set reachable.

## 2. What will mislead you

- **`REGRESSION_TESTS.md` §1's caliper golden and the 8 editor flows are no
  longer Mac-only** — the flows were unlocked (their fixture was always in the
  repo; only the default path pointed at `/Users/mdm`). `run_caliper_test.sh`
  still is: it wants the 10221 sample, which is not in the repo, and
  `DYLD_LIBRARY_PATH`.
- **`bpg_sweep`'s C11 used to fail on every run.** It was the test's own
  arithmetic: it queues 133,333 packets deliberately and then asserted liveness
  with a flat 600 ms. The core answers all of them and returns in 2.26 s
  (~59k packets/s, no crash, no leak, deterministic — measured with
  `flood.mjs`). Fixed by making the liveness budget per-case.
- **`data/BMP_carousel_test` is inside gitignored `data/`.** When it is missing,
  every stream-dependent probe fails with "observer got no stream" and nothing
  says why. `suite_nohw.mjs` materialises it from
  `tools/webctl/fixtures/carousel/`.
- **`--insp` does NOT load `clean_regions`** (`wiringPanel.cpp:10614` vs the
  live path at `:2528-2529`). The offline gate and the live machine disagree
  for any def where clean space matters, silently.
- **A `SKIP` is not a `PASS`.** `hist_wiring` and `play_readiness` both skip on
  this bench for stated reasons (no board ⇒ no `perifCH` ⇒ `cat_ok/cat_ng`
  never published; the fixture carries one margin tag so `maxCount:1` cannot be
  breached). `suite_nohw` keeps the three outcomes apart on purpose.
- **`setThreadPriority` fails for all 7 threads on Windows** (`rc=129`,
  SCHED_RR unavailable). They run at default policy and nothing but seven `[E]`
  lines says so. On macOS they get real RR priorities — so latency measured
  here is not latency measured there.
- **The submodule now tracks `shape_based_matching`'s `ct/dev`**, not the
  personal `ct/opencv5-compat`. `ct/dev` gained the OpenCV 5 guards, the
  completed guard sweep across its test suite, `user_opt_points` (merged in),
  and a CMake gate making its test/bench suite opt-in on Windows — three of its
  53 targets do not compile there and never have.

`uinsp-count` and `uinsp-hist-cell` (+`data-bin`/`data-sel`/`data-value`).
Publish the semantics, not just a handle — the assertion worth making is
usually "the cell claiming to be NG reads the outlet the wiring says is NG",
and the rendered digits have thrown that mapping away.

## 5. Two regressions introduced and fixed the same day

Recorded because they are the shape of mistake this sprint kept making: a fix
that changes a function's contract without following it to its callers.

- `saveSetting` learned to **refuse** a write, but `saveSettingPopUp` still
  pushed `ST MachineSetting` unconditionally — with the panel's *unmerged*
  cache. Before the change the two agreed (both wrong); after it, the file got
  a correct merge while the running core got stale values, and the operator
  read "設定未儲存" while the machine had already taken them.
- `importSetupP` ended in `machineSetupUpdate(after, true)`, and `after` is
  SETTABLE_KEYS-only, so `doReplace` assigned `deviceState = {}` and discarded
  `machine_id`. The strip stamps `dev.machine_id` into every archived batch —
  so a reset taken after a config import filed that batch against `null`.

Both were found by review agents reading the diff, not by any test.
