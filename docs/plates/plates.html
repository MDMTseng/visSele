PLATE 01

這是什麼機器

一顆零件從料斗到料道,會經過六個位置。整台機器的所有軟體, 存在的理由就是在中間那兩格之間把「它長什麼樣」變成「它去哪一道」。

一句話的設計原則: preview 拖慢判定就是缺陷。整條資料路徑每一段都 drop-oldest,不對相機回壓。 看畫面的人可以掉格,判定不行。
PLATE 02

五層,不是三層

多數舊文件寫「三方」。Launcher 是 2026-08-23 之後才有的, SYSTEM_MAP.md 完全沒有它。由上而下,每層只跟相鄰層講話。

世代警告 —— 每個新手都會踩: CoreHub 是二代、uInspESP32_v2 是停滯的重寫、 UI/WebUI2 是新 UI。沒有一個是產線在跑的東西。 除非明確要做二代,不要讀那些目錄。
PLATE 03

埠位圖

四個 TCP 埠加一條序列線。其中兩個埠長得很像而且常被搞混, 所以它們在圖上分開畫。

4098 vs 4099 —— 這一組最容易搞錯

4098launcher 的監督通道

只答 ping(回 pid/uptime/version/git)與 shutdown。 回應帶 pid,因為只靠埠號認不出是誰 —— 上一輪殘留的 core 會用同一個埠回答, 看起來跟剛啟動的子行程一模一樣。曾經真的發生:測試把 shutdown 送給了陌生人。

4099問板子問題的 dev console

可以下 ~58 種板子命令,單一 client —— 第二條連線會把第一條無聲踢掉。 預設不開。產線機器不該只因為某個工程師需要就開控制埠。

過時警告: docs/README.md §2 的鐵則寫 「改問核心的 console:nc 127.0.0.1 4099」。在 launcher 起的 core 上 那個埠是關的,命令會直接連不上。
PLATE 04

開機與更新

版本包自己帶開機配方。launcher 只做三件事:讀 current.json、 照那一版的 boot.js 開起來、盯著它。

這棵樹在 bench 上有兩份,部署錯了不會有人告訴你。 export_v2/ 底下同時有 1.1.104/(soak 與 launcher 實際跑的) 和 app/(自己的 current.json 與另外三個版本目錄)。 「我明明修好了」有兩次都是修到沒在跑的那一份。

PLATE 11

機器正在跑產的時候

FI session 進行中、板子 101 READY。動手之前查這張表。 經驗法則:開序列埠、刪相機、換 session、reset 帶 running 字樣 = 破壞性; GS / 訂閱 / 差值讀數 = 安全。

最貴的十個陷阱

1
machine_setting 的 region 吃掉 golden 基準(三次)
2
!ld 不會載 def 進引擎
3
!fi 太早或重複 —— 全幅 bench 沒開 TRIGMODE_ONCE 會殺相機
4
LineStatusAll 輪詢看不到 ms 等級的脈衝
5
板子的 PIN_ON / PIN_MODE 這版沒有 ack,會默默忽略
6
NVS 計數是壽命值,一律用差值
7
WebUI MAIN + EXIT = SPLASH 死路 —— 只有 HR 能出來
8
合成 DOM 事件無效,要用 Playwright
9
log ring「沒在 log 裡」不代表沒發生
10
git commit -a 會毀 submodule —— 永遠列明路徑
